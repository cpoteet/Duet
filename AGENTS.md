# Duet Agent Guide

## Project boundaries

Duet is a personal Apple Silicon macOS 27+ app for using ChatGPT and Claude in a compact native workspace. Read `README.md` for user-facing installation and usage guidance. `PRODUCT.md` holds product direction; it is git-ignored, so it exists only in local checkouts.

- Keep the project independent of Xcode project files and Swift Package Manager.
- Compile for `arm64-apple-macos15.0` (`LSMinimumSystemVersion` is `15.0`), but list macOS 27 or later as the supported OS on the site and in user-facing docs. The deployment target is a compiler compatibility setting, not a support claim.
- App Store distribution and Intel Macs are out of scope. Releases use Developer ID signing and notarization.
- Keep `Duet` as the user-facing app and bundle name. Don't change the bundle identifier `com.siolon.duet`, so saved sessions and preferences survive renames.

## Structure and commands

- Swift source goes in `Sources/`, bundle resources in `Resources/`, and tests and fixtures in `Tests/` (HTML/JS fixtures in `Tests/Fixtures/`). The site lives in `site/`.
- Code compiles as Swift 6 with `-strict-concurrency=complete` and `-warnings-as-errors`.
- Build with `./build.sh`. It quits any running Duet (and aborts if it can't), compiles with `xcrun swiftc`, assembles `dist/Duet.app`, generates `Duet.icns` from `Resources/DuetIcon.png`, sets the bundle's `CFBundleVersion` to its `CFBundleShortVersionString`, signs, and launches the new build. `DUET_BUILD_ONLY=1` skips the launch.
- Signing uses `DUET_SIGNING_IDENTITY` or the git-ignored `.duet-signing-identity` file. With no identity it signs ad-hoc. A `Developer ID Application:` identity also gets hardened runtime and `Resources/Release.entitlements`.
- Test with `./test.sh`. It builds and runs two test binaries (`Tests/CoreTests.swift` and `Tests/HostLifecycleTests.swift`), compiles every file in `Sources/` (a full compile, since some concurrency errors only appear after type checking), checks that `Info.plist` has microphone and location usage descriptions and matching `CFBundleShortVersionString` and `CFBundleVersion`, and runs `./site-version.sh --check`, so a stale site version fails the tests. The test binaries compile an explicit list of source files, so a new source file that tests depend on must be added to `test.sh`.
- Release with `./release.sh`. It requires a Developer ID Application identity in the keychain and a `notarytool` keychain profile (`DUET_NOTARY_PROFILE`, default `duet-notary`). It runs `./site-version.sh` to copy the version from `Info.plist` into `site/index.html`, builds without launching, signs with Developer ID and hardened runtime, notarizes, staples, and calls `./package.sh`. Commit the updated `site/index.html` with the release; pushing to `main` deploys the site.
- `./package.sh` creates the git-ignored release asset `Duet.zip` with `Duet.app` and `LICENSE.md` at the archive root. It verifies the signature, hardened runtime, stapled ticket, Gatekeeper assessment, matching bundle versions, and archive layout, before and after zipping. Smoke-test the built app before handing off a release when you can.
- `site-version.sh` requires an `X.Y.Z` marketing version. Keep `CFBundleShortVersionString` and `CFBundleVersion` in `Resources/Info.plist` the same for each release.
- The in-app update check reads GitHub's latest-release endpoint for `cpoteet/Duet`, which skips drafts and prereleases, and strips a leading `v` from the tag. Tag production releases `vX.Y.Z` and mark the intended one as Latest. Clients older than the update checker need one manual upgrade.

## App behavior

- Load ChatGPT at `https://www.chatgpt.com` and Claude at `https://claude.ai`. Both web views use the shared persistent `WKWebsiteDataStore.default()`, so sessions normally survive relaunches.
- Each website-data reset (Session menu) removes only the records whose names match that provider's domains (`chatgpt.com`/`openai.com` or `claude.ai`/`anthropic.com`), then recreates its web view. The two resets are independent.
- Show one provider by default and open split view only when asked. In single-pane mode, release the inactive web view to save memory as soon as its outgoing pane lets go of it (not on a timer); website data persists. The Keep both providers loaded setting turns this off for faster switching.
- The When Duet opens setting offers Ask Every Time (the destination chooser), ChatGPT, Claude, Both, or Last Used. Save the workspace size between launches, clamped to the visible display. Center the first workspace window of each launch, and after that keep wherever the user moves it.
- Menu commands: File → New Conversation (Command-N, both panes in split view); View → ChatGPT, Claude, and Both (Command-1, 2, 3) and Equal Widths; Session → Reset ChatGPT/Claude Website Data; Tools → Quick Prompt.
- Quick Prompt opens globally with Control-Option-Space, from Tools → Quick Prompt, and from the Dock icon's menu. Its panel is non-activating: opening it must not bring the workspace forward (unless Duet is hidden, which macOS has to unhide), and it hides when the user clicks into another app. It sends to ChatGPT, Claude, or Both. It recreates each selected provider's web view, waits for the panes to mount, loads a new conversation (`https://www.chatgpt.com/` or `https://claude.ai/new`), sends, and brings the workspace forward. It keeps its text until every selected provider confirms. A Quick Prompt send never opens the shared prompt drawer, even when it enters split view, and it collapses an open drawer unless that drawer holds a draft.
- Keep the primary workspace in its `WindowGroup` so Quick Prompt can reopen it after the window closes. Find the workspace by its stable `NSWindow.identifier` (`com.siolon.duet.workspace`), never by title, and never fall back to some other window.
- The shared native prompt drawer is text-only. It opens when the user enters split view, including when Duet starts in Both but not when a Quick Prompt send enters it, and the toolbar's Prompt button (Command-Shift-P) toggles it. In single-pane mode it offers Send to [current provider] (Command-Return) and Send to Both (Command-Option-Return), and Send to Both switches to split view and waits for both panes to mount first. In split view it offers only Send to Both (Command-Return). While the drawer is open, provider pages can't take keyboard focus unless the user clicks into them or presses Tab.
- Once every selected provider confirms the submission, clear and collapse the drawer draft if it hasn't changed since sending. Keep it if the user edited it afterward or if any submission failed or was ambiguous.
- To send, wait for the provider's composer to appear, fill it, wait for an enabled send control, click it, and treat the composer clearing as confirmation. Refuse to fill a composer that already contains text. Don't confirm by reading the provider's message markup. Show a separate status for each provider, and never retry an ambiguous submission automatically.
- Responses, history, attachments, and provider-specific features stay in the provider pages. Don't scrape or merge provider responses.
- Notifications: an injected Web Notification API shim on HTTPS ChatGPT and Claude main frames forwards site notifications to macOS. A response watcher also watches each adapter's generation indicators (stop buttons, streaming markers, never response text) and posts a "Finished responding" notification when Duet is inactive or the workspace is hidden or minimized. It is controlled by the Notify when responses finish setting (on by default) and suppressed for 10 seconds after a site notification from the same provider. Clicking a notification brings the workspace forward and, outside split view, switches to that provider.
- Bridge `window.print()` to the native print panel. Downloads go through a save panel and are written to a staging file, then renamed into place.
- Support provider-managed sign-in, passkeys, and 2FA. Navigation inside a provider web view is limited to that provider's domains and the Google, Apple, and Microsoft sign-in hosts. Other `http`, `https`, and `mailto` links open in the default browser. Popup windows created by providers also open in the default browser, because disposing a provider-created `WKWebView` can crash. Never collect or store user credentials.
- Grant microphone capture only to HTTPS ChatGPT and Claude origins whose frame and current page are provider pages and not authentication pages, and only from the web view the controller currently owns. macOS still applies its own microphone authorization. Return WebKit's prompt for camera requests. Deny everything else, including authentication, third-party, foreign, stale, spoofed, and non-HTTPS contexts.
- Route geolocation through the native Core Location bridge, with macOS permission handling, and only for HTTPS ChatGPT and Claude main frames that aren't authentication pages. If the page URL changes while a position is being fetched, deny the result. Authentication, third-party, and foreign pages get no location access.
- Keep provider URLs, selectors, readiness and sign-in checks, generation indicators, and injection logic in `ProviderAdapter` and `ChatService`, so a change to one provider's markup stays in its adapter. The Claude adapter also routes Finder file drops through Claude's own file input, because Claude's drop handler gets no entries in an embedded `WKWebView`.
- Keep split-view web-view ownership correct. `BrowserController` owns each `WKWebView`, and `BrowserHostView` only hosts it. A dismantled single-pane host must not remove a `WKWebView` that has moved into a replacement split-pane host, and only a host in the active workspace window may claim the web view.

## Verification

Keep automated tests for provider configuration, dispatch states, generated injection scripts, prompt escaping, local HTML fixtures, the split-pane host lifecycle, startup restoration, workspace sizing, the microphone and location origin gates, and notification rules.

For behavior changes, manually check whichever of these apply: provider login, session persistence, single and split transitions, the prompt drawer, Send to Current, Send to Both, startup destination, window restoration, native permissions, notifications, and the separate website-data resets.

For Quick Prompt changes, also check the global shortcut, the Tools menu entry, and the Dock menu item, that opening the panel leaves the workspace where it is, that each destination opens a new conversation, that both split panes mount before sending to Both, and that a hidden or minimized workspace comes back.
